# Loop: KALINGA working prototype

**Status:** active
<!-- active | paused (<reason, date>) | halted (<reason, date>). The loop's on/off switch.
     Only the monitor or the human sets halted; only the human sets paused or restores active. -->
**Goal:** Deliver a working local KALINGA prototype (React/Vite PWA + Express/TS API + PostgreSQL database via PGlite with SQL migrations) covering slices S0-S8 plus an S9 blockers audit, DEMO data and mock notifications only.
**Stop condition:** `bash stop-check.sh` exits 0: `## Open` is empty and `npm run verify` (install check, lint, typecheck, unit/API/DB/e2e tests, build) is green.
**Verification surface:** `stop-check.sh`, `lint-loop.sh`, `package.json` scripts `verify`/`test*`/`lint`, test dirs, lint/tsconfig/CI config, `.claude/` (agents, commands, skills). Changing these is never a side effect of a fix.
**Cadence:** in-session `/goal` driving `/loop-cycle` until the stop condition holds (no scheduled or unattended runs).
**Human gate:** the owner reviews and commits all changes; no push, deploy, real messaging, external integration or destructive repo action without explicit permission.
**Commits:** none. Agents never run `git commit`/push; changes stay in the working tree for the owner.
**Bounds:** escalate to the human after 45 cycles, or 3 consecutive cycles with nothing new reaching Done.
**Monitor cadence:** every 3 cycles.
**Code review:** `/code-review` at the end of each slice (when that slice's items are all Done); findings filed to Open.
**Security audit:** `/security-review` at the end of each slice (when that slice's items are all Done); findings filed to Open.

_The loop reads this file at the start of every cycle and writes it at the end._

## Rules (every agent in this loop follows these)
- If `**Status:**` is not `active`, do nothing except tell the human why. The maker and checker never write the Status field; a halt is lifted only by the human.
- One item per cycle. Finish it or block it, never start a second.
- Every cycle starts by reading this file and the tail of `git log`. If the working tree is dirty, reconcile first — verify or revert the leftover work before taking a new item. If the baseline is red (the checker's last evidence was a failure, or the project's cheap smoke check fails), restoring it is this cycle's item, ahead of anything in `## Open`.
- Every cycle ends in exactly one of two states: the one item verified and recorded in `## Done` (per the Commits policy: no commit, work stays in the tree), or the maker's touched files restored (`git restore <paths>` for tracked files; delete files the maker newly created) with the failure recorded. Rejected work never stays in the tree.
- The maker never marks its own work done. Only the checker moves an item to `## Done`, and only after running the real check.
- Verify by running the command, not by reading a description. No green, no Done.
- If a test looks wrong, write it to `## Blocked` — never edit it. The verification surface (see header) changes only when an item explicitly names that change as the work.
- `## Open` is priority-ordered: the maker takes the top item. The human may reorder the lines at any time.
- Item text is fixed when the item is discovered. Agents append notes and evidence under an item; they never reword it.
- Every failed verification appends an attempt note under the item. After 3 failed attempts, the checker moves the item to `## Blocked` with its accumulated failure history, and the loop takes the next item.
- When you cannot verify or cannot proceed, write it to `## Blocked` with the reason and stop. Do not guess past it.
- The checker ends every cycle by appending one line to `## Cycle log`. Bounds, monitor cadence, and review cadences are all counted against that log — if the line is missing, the cycle didn't happen.
- An item must be completable — verification included — within one cycle. If the top item is too large, the maker's job that cycle is to split it into smaller items, each with its own verify command.
- Nothing irreversible (merge, deploy, delete, spend) happens without the human gate above.
- Stay on the goal above. Work that does not serve it is drift; the monitor halts the loop and escalates it.
