# Run guide (prototype)

Local DEMO prototype only. Nothing here is a real service, clinic or account.

## Prerequisites

Node.js 20 or newer (the loop was run on Node 24) and npm. No database server, accounts or external services are needed: the API uses an embedded PGlite database. The project was developed on Windows 11.

## Start

`npm install` once, then `npm run dev` (API http://localhost:3001, web http://localhost:5173). In development the API seeds fictitious DEMO content on start (refused outside `DEMO_MODE=true` with `NODE_ENV` development or test).

## DEMO staff accounts (S6)

Staff accounts are created at seed time with scrypt hashes generated by the application (`apps/api/src/staff/demo-seed.ts`); no password hash or real e-mail is stored in the repository. All addresses use the reserved `.invalid` domain, and these accounts cannot sign in when `DEMO_MODE` is off.

| E-mail | Role | Clinic membership |
|--------|------|-------------------|
| `staff.a@demo.invalid` | clinic_staff | DEMO Clinic A |
| `admin.a@demo.invalid` | clinic_admin | DEMO Clinic A |
| `staff.b@demo.invalid` | clinic_staff | DEMO Clinic B |
| `provincial@demo.invalid` | provincial_admin | none (not a booking reader) |
| `tech@demo.invalid` | technical_admin | none (not a booking reader) |
| `disabled@demo.invalid` | clinic_staff, deactivated | cannot sign in |

DEMO password for all accounts: `demo-staff-only-2026` (override before seeding with the environment variable `DEMO_STAFF_PASSWORD`, at least 12 characters). It protects nothing real. Existing accounts are never re-hashed on re-seed, so delete the PGlite data directory to change the password of an already seeded database.

Staff API (all responses `Cache-Control: no-store`; state-changing calls need the `X-CSRF-Token` returned by `POST /api/v1/staff/login` or `GET /api/v1/staff/me`, and decisions need `If-Match`): see decisions D-025 to D-031 in `docs/decision-log.md`. Gap G-AUTH: this is a dev equivalent of Supabase Auth and must be replaced before any real use.

## DEMO assistant

A rule-based DEMO assistant is the floating button at the bottom right of every page inside the app shell (code in `apps/web/src/assistant/`). It has no LLM and no network access, suggests chips for the current page, puts the urgent exposure path first, and its "talk to a real health professional" reply says honestly that no clinician is connected.

## Verify and end-to-end tests

- `npm run verify` runs the loop harness test, lint, typecheck, all workspace tests and builds.
- `npm run test:e2e:install` once (downloads Chromium for Playwright; needs network), then `npm run test:e2e`. Playwright starts its own API with a fresh in-memory database plus the web app, so free ports 3001 and 5173 or stop `npm run dev` first if they clash. The suite is not meant for a long-lived seeded server.

## Reset the database

By default `PGLITE_DATA_DIR` is empty (see `.env.example`), which means an in-memory database: restart `npm run dev` and everything is re-seeded. If you set `PGLITE_DATA_DIR` to a folder, stop the API, delete that folder and start again to get a fresh seed (this is also how to change the DEMO password of an already seeded database).

## Known limitations

- Everything is DEMO: clinics, articles, staff accounts and translations. DEMO accounts exist only when `DEMO_MODE=true`.
- Filipino text is a draft and has not been linguistically or clinically reviewed.
- Reminders use a mock transport only; nothing is sent by SMS or e-mail.
- A booking submission is a request. Only clinic staff can confirm it, and the app never says "booked" on submission.
- Real booking for ages 15-17 is disabled (the approved SOP artifact is missing); under 15 is refused.
- Staff auth is a dev equivalent (gap G-AUTH); the API connects to the database as owner, so server-side checks, not RLS, are the active boundary.
- Not tested on real devices, screen readers, slow networks or under load. See `docs/implementation-status.md` and `docs/launch-gates.md`.
